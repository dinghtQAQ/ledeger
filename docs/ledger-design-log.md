# 记账项目需求访谈记录

记录日期：2026-09-02

这份文档保存此前 `grill me` 访谈的决策路径。它不是新的实现规范；当前领域词汇以 [CONTEXT.md](../CONTEXT.md) 为准，长期决策以 [ADR](./adr/) 为准。

## 轮次一：先确定账本边界

1. 不采用复式记账，先做单式记账。
2. 项目只服务一个用户，当前只有一个逻辑总账，不对应真实银行卡、微信或支付宝。
3. 账目类型确定为收入、普通支出和到期支出。
4. 到期支出是需要记录到期时间、但不在付款时重复计入的支出。

对应决策：[ADR-0001](./adr/0001-single-logical-ledger.md)、[ADR-0003](./adr/0003-due-expense-lifecycle.md)

## 轮次二：把“不丢数”拆成可验证的规则

1. 真实金额与显示金额分离：业务计算不能使用显示后的三位小数。
2. 金额使用人民币正数，最多保留四位小数；超过四位按半入规则归一化。
3. 原始金额为 `100.0016` 时，后续业务应以该四位精度金额为依据；拆分后的合计必须保持一致。
4. 不保留超过四位的小数原始输入；显示时最多三位并再次按半入规则舍入。
5. 支出不使用负数表达，方向由账目类型表达。

对应决策：[ADR-0002](./adr/0002-canonical-money-and-reversal.md)

## 轮次三：确定错误修正和到期状态

1. 不提供通用编辑接口；金额或类型记错时，通过冲正后重新入账。
2. 冲正保留原账目，生成等额反向账目；同一账目只能冲正一次，合计必须归零。
3. 到期支出状态确定为 `unpaid`、`paid`、`cancelled`。
4. 付款只改变状态；冲正会将到期支出置为 `cancelled`，之后不能再付款。

对应决策：[ADR-0002](./adr/0002-canonical-money-and-reversal.md)、[ADR-0003](./adr/0003-due-expense-lifecycle.md)

## 轮次四：确定查询、鉴权和时间边界

1. 业务接口必须鉴权，密钥从 Worker secret 或变量读取，鉴权失败返回 `403`。
2. `/health`、数据库健康检查和 API 文档保持公开。
3. 查询必须支持游标分页、日期筛选、分类筛选和排序。
4. 数据库存 UTC，日期筛选默认按东八区解释；时区可由 Worker 变量覆盖。
5. 写入使用幂等键；并发假设较低，因此采用乐观并发控制。

对应决策：[ADR-0004](./adr/0004-api-safety-and-time-boundaries.md)

## 轮次五：确认部署与延期项

1. 数据库使用 D1，表结构通过 migration 管理。
2. 个人生产 D1 的 `database_id` 不写入公共仓库，使用未提交的部署配置。
3. 暂不实现备份、导出、前端、拆分记账、复式记账、分期、利息、自动扣款和外部账户映射。
4. 分类表未来可以支持粗类和细类，但当前只保留可选分类标签。

对应决策：[ADR-0005](./adr/0005-d1-and-private-deployment-config.md)

## 设计树的当前边界

```text
单用户个人总账
├── 单式记账
├── 一个逻辑账户
├── 收入 / 支出 / 到期支出
│   ├── 到期支出：unpaid → paid
│   └── 冲正：任意可冲正账目 → cancelled（到期支出）或 reversed_at（其他账目）
├── 业务精度四位，显示精度三位
├── 冲正代替编辑和删除
└── D1 + 鉴权 + 幂等写入 + 游标查询
```

# 记账项目需求访谈记录

记录日期：2026-09-02

这份文档保存此前 `grill me` 访谈的决策路径。它不是新的实现规范；当前领域词汇以 [CONTEXT.md](../CONTEXT.md) 为准，长期决策以 [ADR](./adr/) 为准。

## 轮次一：先确定账本边界

1. 不采用复式记账，先做单式记账。
2. 项目只服务一个用户，当前只有一个逻辑总账，不对应真实银行卡、微信或支付宝。
3. 账目类型确定为收入、普通支出和到期支出。
4. 到期支出是需要记录到期时间、但不在付款时重复计入的支出。

对应决策：[ADR-0001](./adr/0001-single-logical-ledger.md)、[ADR-0003](./adr/0003-due-expense-lifecycle.md)

## 轮次二：把“不丢数”拆成可验证的规则

1. 真实金额与显示金额分离：业务计算不能使用显示后的三位小数。
2. 金额使用人民币正数，最多保留四位小数；超过四位按半入规则归一化。
3. 原始金额为 `100.0016` 时，后续业务应以该四位精度金额为依据；拆分后的合计必须保持一致。
4. 不保留超过四位的小数原始输入；显示时最多三位并再次按半入规则舍入。
5. 支出不使用负数表达，方向由账目类型表达。

对应决策：[ADR-0002](./adr/0002-canonical-money-and-reversal.md)

## 轮次三：确定错误修正和到期状态

1. 不提供通用编辑接口；金额或类型记错时，通过冲正后重新入账。
2. 冲正保留原账目，生成等额反向账目；同一账目只能冲正一次，合计必须归零。
3. 到期支出状态确定为 `unpaid`、`paid`、`cancelled`。
4. 付款只改变状态；冲正会将到期支出置为 `cancelled`，之后不能再付款。

对应决策：[ADR-0002](./adr/0002-canonical-money-and-reversal.md)、[ADR-0003](./adr/0003-due-expense-lifecycle.md)

## 轮次四：确定查询、鉴权和时间边界

1. 业务接口必须鉴权，密钥从 Worker secret 或变量读取，鉴权失败返回 `403`。
2. `/health`、数据库健康检查和 API 文档保持公开。
3. 查询必须支持游标分页、日期筛选、分类筛选和排序。
4. 数据库存 UTC，日期筛选默认按东八区解释；时区可由 Worker 变量覆盖。
5. 写入使用幂等键；并发假设较低，因此采用乐观并发控制。

对应决策：[ADR-0004](./adr/0004-api-safety-and-time-boundaries.md)

## 轮次五：确认部署与延期项

1. 数据库使用 D1，表结构通过 migration 管理。
2. 个人生产 D1 的 `database_id` 不写入公共仓库，使用未提交的部署配置。
3. 暂不实现备份、导出、前端、拆分记账、复式记账、分期、利息、自动扣款和外部账户映射。
4. 分类表未来可以支持粗类和细类，但当前只保留可选分类标签。

## 轮次六：第二阶段前端与统计范围

1. 第二阶段前端优先采用前后端同源部署：前端 SPA 与 Worker API 由同一个 Cloudflare Worker 提供，避免额外服务器和跨域边界。
2. 业务认证改为单账户登录会话；浏览器不直接持有生产 API key，会话使用带过期时间的安全 Cookie。
3. 当前产品只新增和分析收入、普通支出；旧版到期支出字段和接口暂时保留用于兼容，但前端不提供新增入口，也不纳入分析。
4. 冲正记录保留在账目列表中，但冲正及其原账目不参与分析统计。
5. 余额定义为收入减普通支出；不通过定时任务刷新业务状态，也不记录信用卡实际付款日。
6. 分析周期以用户配置的发薪日为锚点，默认每月 20 日，可调整为每月 1 至 28 日；周期从锚点日开始，到下一个锚点日前一天结束。
7. 支出必须选择一个粗类：住房、餐饮、交通、公用、健康、娱乐、投资；细类暂不强制，收入分类可为空，历史空分类显示为“未分类”。

本轮决策：

1. 单账户登录密码由 Worker Secret 提供，不做注册和多用户；登录后使用带过期时间的 HttpOnly 安全 Cookie 会话。
2. 会话采用 7 天滑动有效期，访问期间续期，过期后重新登录。
3. 账目列表默认展示全部记录，包括原账目和冲正记录；冲正记录带明确标识，不允许再次冲正，并可与原账目关联查看。
4. 分析页默认展示当前工资周期，并支持周期切换和自定义日期范围。
5. 粗类由数据库配置维护，前端通过接口读取；当前七个粗类作为初始数据，细类暂不强制。
6. 首版分析采用实时聚合 SQL 与索引，暂不引入统计快照或 Cron 缓存；后续根据真实查询性能再优化。
7. 前端采用 React、Vite、TypeScript SPA，由同一个 Cloudflare Worker 托管静态资源和 API，前后端同源部署。

本轮问题已在轮次七至九中完成确认。

## 轮次七：认证、分类和分析首版

1. 写请求使用安全 Cookie 会话，并校验同源 `Origin`/`Referer`；首版不额外引入 CSRF Token。
2. 登录页只有密码输入，不区分账户；每次登录都要求 Cloudflare Turnstile，另加轻量失败限速。
3. 会话采用 7 天滑动有效期，访问期间续期，过期后重新登录。
4. 粗类使用固定数字 ID 与文字条目，作为系统字典，不提供增删改管理；初始粗类为住房、餐饮、交通、公用、健康、娱乐、投资。粗类表只保存 ID 和文字。
5. 细类使用数字 ID 和粗类 ID 关联；细类可以新增、改名、排序和停用，但不可删除已存在的细类记录。
6. 分析页作为登录后的默认首页；首版默认展示当前工资周期，周期可切换或自定义日期。
7. 首版图表按所选期间内的分类汇总金额，横轴为粗类、纵轴为金额；同时返回金额和笔数，排除冲正及其原账目，并提供开关切换为细类视图。
8. 首版不做月度、季度、年度专门分析页；分析采用实时聚合 SQL，暂不引入快照或 Cron。
9. 生产环境当前无历史数据，因此不为旧版到期支出设计前端兼容流程；第二阶段新增接口直接只接受收入和普通支出。

本轮问题已在轮次八至九中完成确认。

## 轮次九：方案冻结

1. 新增记账表单默认类型为普通支出；字段顺序为类型、粗分类、可为空的细分类、金额、备注，发生时间默认当前时间。
2. 分析页同时展示“周期净额”和“当前余额”：周期净额受所选日期范围影响，当前余额统计全部有效收入减普通支出。
3. 分析金额以十进制字符串返回，前端只负责格式化展示，不使用浮点数作为业务计算依据。
4. 登录接口为 `POST /auth/login`，请求包含密码和 Turnstile token；成功后返回认证状态与过期时间并设置会话 Cookie。`GET /auth/session` 查询会话，`POST /auth/logout` 注销当前会话。
5. 分类接口提供粗类只读查询，以及细类新增、修改、停用；账目保存粗类 ID 和可空细类 ID，后端校验细类必须属于所选粗类。
6. 分析摘要接口通过 `level=coarse|fine` 切换聚合层级；细类结果带所属粗类 ID 和名称；空分类统一归入“未分类”。
7. 列表筛选增加账目类型、粗类 ID、细类 ID；默认展示全部记录。冲正原账目和冲正记录仅在列表出现，不进入分析。
8. 工资周期和自定义日期范围的边界规则已冻结：周期按既有时区配置计算，自定义日期在界面上包含结束日，服务端使用排他结束边界。
9. 本轮只记录方案，不修改源代码；实现必须按迁移、认证/API、前端、测试、部署顺序拆分。

## 轮次八：接口契约与首版交互

1. 细类表允许新增、改名、排序和停用，字段包含数字 ID、名称、所属粗类 ID、排序值和启用状态；粗类表只包含数字 ID 和名称，并作为固定字典维护。
2. 账目使用 `category_id` 和可空的 `subcategory_id`；支出必须有粗类，细类必须属于该粗类，收入的分类字段可为空。
3. 分析使用统一摘要接口，通过 `level=coarse|fine` 切换聚合层级；返回收入总额、支出总额、余额，以及分类金额和笔数。冲正原账目与冲正记录均排除，空分类归入“未分类”。
4. 工资周期按 `LEDGER_TIMEZONE` 计算，使用 `[from, to)` 半开区间；发薪日为每月 1 至 28 日，当前周期示例：2026 年 9 月 2 日、发薪日 20 日时，周期为 2026 年 8 月 20 日至 2026 年 9 月 20 日（不含）。
5. 自定义日期在界面上表现为包含起止日，API 内部把结束日转换为下一天的零点作为排他边界。
6. 新增记账表单字段顺序为：类型、粗分类、可为空的细分类、金额、备注；发生时间默认当前时间。
7. 列表提供新增、详情和确认后冲正；不提供编辑、物理删除或付款操作。已冲正账目和冲正记录不可再次冲正。
8. 登录成功后默认进入 `/analytics`；列表为 `/entries`，新增为 `/entries/new`，设置为 `/settings`。

本轮只剩一个交互默认值待确认：新增记账表单的“类型”是否默认选择普通支出。

对应决策：[ADR-0005](./adr/0005-d1-and-private-deployment-config.md)

## 设计树的当前边界

```text
单用户个人总账
├── 单式记账
├── 一个逻辑账户
├── 当前新增：收入 / 普通支出
│   └── 旧版到期支出仅作兼容历史展示，不进入第二阶段分析
├── 业务精度四位，显示精度三位
├── 冲正代替编辑和删除
├── 固定粗类 + 可停用细类
├── 可配置发薪日的工资周期
├── 同源 React/Vite SPA + 单账户滑动会话
└── D1 + 实时聚合分析 + 游标查询
```

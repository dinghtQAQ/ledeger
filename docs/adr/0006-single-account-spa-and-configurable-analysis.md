# 使用同源单账户 SPA 与可配置工资周期分析

**Status: accepted**

第二阶段采用 React、Vite、TypeScript 单页前端，并由同一个 Cloudflare Worker 与 API 同源提供。业务访问不再依赖浏览器携带 API key，而使用单账户密码登录后建立的安全 Cookie 会话；会话有效期为 7 天，并在有效访问期间滑动续期。每次登录都要求 Cloudflare Turnstile，并配合轻量失败限速。

分析页作为登录后的默认首页，默认展示当前工资周期。工资周期使用既有 `LEDGER_TIMEZONE`，发薪日默认为每月 20 日，可设置为 1 至 28 日。首版只做周期内按粗类汇总的柱状图和对应统计，不提前引入月度、季度、年度专门分析页或统计快照。

支出分类采用两级模型：粗类是固定数字 ID 字典，不提供增删改管理，粗类表只保存 ID 和文字；细类使用数字 ID 关联粗类，并保存排序值和启用状态，可以新增、改名、排序和停用，但不删除已存在的细类。支出必须选择粗类，细类可为空；收入分类可为空。分析柱状图默认按粗类展示，并可切换为细类。

首版分析接口使用日期范围和 `level=coarse|fine`，返回收入总额、普通支出总额、余额，以及分类金额和笔数。工资周期使用现有时区配置计算半开区间；自定义日期在界面上包含结束日，服务端转换为排他结束边界。冲正原账目和冲正记录均排除在分析之外，但全部保留在列表中。

## Consequences

- 前端与 API 可使用同一站点路径，首版不需要额外前端服务器或跨域配置。
- Cookie 写请求必须执行同源来源校验；会话过期后前端回到登录页。
- 登录密码只保存在 Worker Secret；数据库只保存会话信息，不保存账户密码。
- 分析首版依赖实时聚合 SQL 和现有索引，后续只有在真实性能不足时才增加汇总快照。
- 粗类变更需要代码或 migration 发布；细类停用后仍需支持历史账目展示。
- 分析摘要同时提供所选期间的周期净额与不受日期筛选影响的当前余额，金额以十进制字符串传输。
- 新增记账只接受收入和普通支出；旧版到期支出字段可以继续留在存储模型中，但不进入第二阶段前端与分析。
